# Threads 自動投稿の設計

2026-11-25。状態：坂本さんの承認待ち。【坂本】＝本人が決めたこと、【提案】＝こちらの判断（承認のときに直せる）。

## 目的
flat. をまだ知らない近くの人に、次を知ってもらう。【坂本】
1. 店のイベントと営業時間
2. 彦根駅・彦根城の近くに、夜遅くまで開いている夜カフェがあること（例「夜の居場所を探されているかたぜひflat.へ！」）
3. 毎週木曜20時のランクラブ（例「毎週木曜日20時から走っています！」）

## 決まっていること【坂本】
- 文面は毎回AIが新しく書く
- 前の日に下書きを作り、/threads に出す。直す・止めるができ、何もしなければ自動で投稿する

## やらないこと
- 返信・いいね・フォローの自動化、反応の分析、他のSNSへの転載、動画
- 画面からの自由な手動投稿（Threadsアプリでする）
- 避けたい失敗：お客様の情報が出る／中止のイベントを告知する／似た投稿が並ぶ／同じものが2回出る／休みの日に「開いています」と出る

## 作り方
| 案 | 良い点 | 悪い点 |
|---|---|---|
| **1. /threads を別に作り、計算と休業日はインスタと共有（これで進める）** | 下書きが見やすい。インスタに影響しない | 画面が1つ増える |
| 2. /instagram に欄を足す | 画面は1つ | もう欄が多く、下書きが埋もれる |
| 3. Buffer など外部サービス | 作らなくていい | 予定表と営業時間を材料にAIで書く部分がない |

案1を勧めると伝え、案1で進めると言ってある。これに反対は出ていない。

## 投稿の決まり【提案】
- 1日1回、19:00。営業日だけ（定休の火曜と、/instagram と共通の臨時休業 `ig:closures` の日は出さない）。時刻は画面で変えられる（7:00〜22:30）
- ただし下書きの中身が出す時刻に合うようにする。イベント当日の告知は、開始に間に合わないと意味がないので、**当日ではなく前日と3日前**に出す。前日が休みならその前の営業日。ランは木曜20時なので**前日の水曜**に「明日」として出し、木曜には出さない
- テーマは1日1つ。上から順に当てはめる
  1. 前日告知：翌日（翌日が休みなら次の営業日まで）のイベント。複数あれば1つの投稿にまとめる
  2. 3日前告知：3日後のイベント。3日前が休みなら、その前の投稿日に出す。ランは前日告知だけで、3日前は出さない
  3. それ以外：「夜の居場所」「営業時間」「場所（彦根駅・彦根城の近く）」「ランクラブの紹介」を順に回す。直前に出したテーマは続けない
- ランも予定表のイベントとして扱う。予定表にない週のランは、日付つきで告知しない
- 「ランクラブの紹介」は「毎週木曜20時」と一般の形で書く。ただし次の木曜が予定表に無いときはこのテーマを飛ばす（「今週は休み」なのに誘うことになるため）。11/26は予定表に無いので、この決まりで自然に外れる

## AIに渡す材料
- `lib/shop.ts` の店名・カフェの営業時間・ラストオーダー・定休日・住所（バーの時刻は下の決まり）
- 画面で編集できる「店の紹介メモ」（下記の初期値）。AIはここと上の情報、告知するイベントの公開情報だけで書く
  - 初期値：彦根駅・彦根城の近く／夜の居場所を探している人に来てほしい／ランは毎週木曜、19:50 flat.集合・20:00スタート・約30分・キロ5分〜5分30秒・話しながら走れるペース・参加はインスタのDM／走った後は flat. で休憩（注文しなくてもいい）
- 直近14回の投稿文（似た文を避けるため）
- 【坂本 11/25】夜は24時に閉店、ラストオーダー23:30。投稿には「24時まで（ラストオーダー23:30）」と書き、24時半とは書かない。`SHOP.hours` のバーはまだ 24:30 なので、直るまではAIにバーの終わりの時刻を渡さず、店の紹介メモのこの1行を渡す（`SHOP` を直すかは坂本さんに確認中）
- 書き方：日本語、300字以内、絵文字は0〜2個、ハッシュタグ本文中は無し、材料に無い値段・メニュー・人数・実績は書かない。営業中かを断定する言葉（「今開いています」）は使わない

## イベントは「告知する」を押したものだけ
/schedule には貸切のお客様の名前・電話番号・金額・社内メモ・仮の予定が入っている（例：12/30の同窓会の予定）。そのため：
- /threads に今後のイベントを並べ、1件ごとに「告知する」を押す。**初期はすべてオフ**
- 押したときに「公開用の一文」を入れる（開始時刻・内容など）。日付と `title`・この一文だけをAIに渡す。`place`・`note` は渡さない（タイトルも画面で公開用に直せる）
- 予定表から消えた、または日付が変わったイベントは、告知をオフに戻し、下書きも捨てて作り直す
- 木曜のラン（木曜で、タイトルが「ランニングクラブ」のもの）だけは「毎週告知する」の継続スイッチを置く（初期オフ）。あとから予定表に足した週にも効き、公開用の一文は共通。土曜のランは1件ずつ押す。`endDate` のある複数日のイベントは初日を基準にする

## 1日の流れ
1. 前日22:00：翌日が投稿する日なら、テーマを決めてAIが下書きを作る。失敗したら22:55まで5分おきに作り直す。下書きは1日1件
2. 22:00〜翌日の投稿時刻：画面で本文を直す／止める／作り直す。止めた日は出さない（戻せる）
3. 投稿時刻：その日の下書きを出す。出す直前に、休業日でないこと、告知のイベントがまだあり、日付もオンも変わっていないことを確かめる。変わっていれば、その場では書き直さずに出さず、履歴に理由を残す
4. 時刻を30分過ぎたら出さない（`LATE_LIMIT_MIN`）。下書きがない日も出さない
- 下書きの後でイベントが変わったら：5分おきの cron が気づいたら下書きを捨て、投稿時刻の15分前までなら作り直す（手で直した分も消える。画面に「イベントが変わったので作り直しました」と出す）。その後に変わったら、その日は出さない。後から「告知する」を押しただけでは今の下書きは変えず、［作り直す］で入れる
- 貸切や営業時間が違う日のために、/threads に「出さない日」を持つ（前もって日付で入れる。インスタには影響しない）。12/30・12/31 のような日は坂本さんが入れる
- 同じ日の投稿は KV の `nx` ロックで1回だけ。失敗時の扱い：コンテナ作成で失敗したら次のcronでやり直す。公開の呼び出しが不明な結果（タイムアウトなど）のときは、自動でやり直さず「確認してください」と出す（二重投稿を防ぐ）
- 本文はAIが作っても人が直しても、500字（Threadsの数え方。絵文字はUTF-8のバイト数）と、電話番号・メールアドレス・金額らしい文字列を検査する。下書きの生成で引っかかったら1回作り直し、だめなら下書きを「止めた」状態にして理由を出す。人が直したものは500字だけで止め、他は注意を出す。公開用の一文に書いた金額は、そのまま本文に使ってよい。公開用の一文に電話番号・メールアドレスは入れられない（保存させない）

## 画像
最初は文章だけ。ランの日に画像を付ける案は前に出したが、Threadsは横長や正方形の文章つき投稿と違い、縦長のストーリー用画像が合わないので最初は外す。後から足せる。【提案】

## Threadsとのつなぎ方
- Metaアプリ flat-auto-video に Threads の用途を足し、flat.hikone を Threads テスターにする。自分のアカウントへの投稿だけならアプリ審査は不要（Metaの説明による）。アカウントは投稿の公開範囲を「公開」にしておく
- 権限は `threads_basic` と `threads_content_publish`
- 認可コードからトークンを取る（ThreadsのアプリIDとシークレット、コールバックURLが要る）。シークレットは Vercel の環境変数 `THREADS_APP_ID` / `THREADS_APP_SECRET` に入れる。`/api/threads/authorize` と `/api/threads/callback`（middleware の合言葉なし一覧に callback を足し、`state` を検証する）。1時間のトークンを60日のトークンに交換し、KVにサーバー側だけで持つ
- 60日で切れるので、cronで7日ごとに延ばす（`refresh_access_token`、24時間以上たっていること）。切れると延ばせないので、画面でつなぎ直す。残り10日を切ったら画面に赤く出す
- 投稿：`POST /{user-id}/threads`（`media_type=TEXT`、`text`）→ 約30秒待つ／`status` が `FINISHED` → `POST /{user-id}/threads_publish`。ホストは `graph.threads.com/v1.0`。`is_made_with_ai` という任意の項目があるので、付けるかは坂本さんに決めてもらう（初期は付ける）
- 本人がすること：Metaの画面での設定・テスター承認・認可、シークレットを Vercel に入れること。チャットには貼らない

## 画面 /threads（上から）
1. 接続（つなぐ／残り日数／最後のエラー）と「自動投稿」のオンオフ（**初期はオフ**）
2. 次の下書き：本文の編集欄・字数・テーマ・投稿予定の時刻・［保存］［この日は出さない］［作り直す］
3. 告知するイベント（前述）
4. 店の紹介メモ・投稿時刻
5. 履歴（出した／出さなかった・理由／失敗、Threadsへのリンク）
メニューは「インスタ」の隣に「Threads」。既存の画面と同じ作り。styled-jsx は使わない（過去の事故）。

## 部品
- `lib/threadsPlan.ts`：計算だけ（投稿日か、テーマ、文面の検査）。テスト `lib/threadsPlan.test.ts` を `package.json` の test に足す
- `lib/threads.ts`：KV（`th:conn` `th:settings` `th:events` `th:drafts` `th:runs`）、AI、Threads API
- `app/api/threads/route.ts`、`app/api/threads/authorize`・`callback`、`app/api/cron/threads/route.ts`
- `vercel.json` に5分おきの cron（インスタと同じ時間帯 7:00〜22:55）。cronの認証はmiddlewareの `isCronCall` に任せる（他のcronと同じ）
- AIは `@anthropic-ai/sdk`（既存の鍵）。構造化して `text` だけを受け取る。モデルは作る人が最新の資料で決める。1日1回なので費用は小さい

## 出すまで
自動投稿はオフのままデプロイする。初回は下書きを2〜3日見てから坂本さんがオンにする。ローカルの開発サーバーは使わず、`next build` とテストを通し、本番で確かめる。この作業は `~/system` で別の作業が同時に進んでいるので、自分のファイルだけをコミットする。

## 作る人に任せること
AIへの指示文の細部、画面の見た目、モデル、KVの細かい形、エラー文。
